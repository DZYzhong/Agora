# Agora 真实团队工作流架构说明

## 一句话定位

Agora 是面向软件研发团队的低感知 AI 协作记忆层。开发者、测试/质量人员、项目经理主要通过各自的 AI 工具工作；Agora 在背后保存、复用、治理和审计项目上下文、项目资产、技能包、团队经验和任务过程。

Agora 的目标不是替代 AI 工具，也不是让每个开发者频繁打开 Web UI。Agora 的价值是让团队共享一致的项目理解、降低 token 浪费、规范 AI 工具工作流程、沉淀团队资产，并减少结果对个人经验水平的强依赖。

## 角色

### 开发人员

开发人员 A、B、C 分别处理同一项目的不同任务。他们日常在 AI 工具、IDE、Terminal 中工作，不直接管理 Agora。

开发人员需要从 Agora 获得：

- 项目统一上下文。
- 项目开发流程。
- 已批准技能包。
- 历史任务经验。
- 当前任务应产出的文档模板和质量要求。

开发人员需要向 Agora 沉淀：

- 本次任务的过程文档。
- 自测结果。
- 任务上下文更新。
- 可复用经验或候选 skill。

### AI 工具

AI 工具是开发人员、质量人员、项目经理使用 Agora 的主要入口。

AI 工具负责：

- 识别当前本地项目、Git 状态和任务名称。
- 查询 Agora 中已有项目上下文和技能包。
- 在缺失或过期时扫描本地项目并生成上下文。
- 按项目流程引导开发人员完成任务。
- 在每个流程节点输出固定文档。
- 将任务过程、上下文更新、候选 skill 上传 Agora。
- 在需要人工判断时让使用者在 AI 工具中介入审查。

### 项目经理 / 技术负责人 / 管理员

项目经理或技术负责人显式使用 Agora Web UI 做治理。

他们负责：

- 审核和合并任务上下文更新。
- 审核项目上下文是否跑偏。
- 审批候选 skill 入库。
- 管理项目流程和文档规范。
- 查看项目任务状态。
- 查看团队资产和项目资产。
- 管理团队成员、项目权限和审计过程。

### 质量人员

质量人员可以通过 AI 工具获取：

- 当前项目质量状态。
- 某个任务的质量状态。
- 风险点、测试覆盖、回归建议。
- 任务流程中自测和评审产物。

质量人员也可以通过 Agora Web UI 查看审计和质量资产。

## Agora Web UI 定位

Agora Web UI 不是开发者日常主工作台。

Web UI 主要用于：

- 可视化项目 AI 上下文。
- 可视化项目资产、团队资产、技能包。
- 审计任务过程。
- 审批上下文合并。
- 审批 skill 入库。
- 管理项目流程。
- 管理团队和权限。
- 查看项目和任务状态。

开发者日常体验应该是低感知的：他们继续使用 AI 工具，Agora 在背后保存和复用项目经验。

## 项目上下文主流程

1. 开发者打开本地项目并使用 AI 工具。
2. AI 工具识别项目、Git remote、branch、commit、dirty workspace 状态。
3. AI 工具向 Agora 查询该项目是否已有可用上下文和 skill 包。
4. 如果 Agora 已有新鲜上下文，AI 工具直接使用。
5. 如果 Agora 没有上下文或上下文过期，AI 工具扫描本地代码和文档。
6. AI 工具生成项目 ContextPack，并上传 Agora。
7. 项目经理或技术负责人可以在 Web UI 中审核。
8. 审核通过后的 ContextPack 成为团队共享上下文。
9. 后续开发人员复用该上下文，避免重复全量分析。

## 任务开发流程

每个项目可以配置自己的开发流程。流程可以由项目经理在 Web UI 中维护，也可以由管理员通过 AI 工具生成后提交到 Agora 审批。

一个典型任务流程是：

1. 分析。
2. 设计。
3. 评审。
4. 开发。
5. 自测。
6. 上传/交付。

每一步都应该：

- 有固定文档产出。
- 同步保存到项目本地。
- 上传或同步到 Agora。
- 允许人在 AI 工具中审查和确认。
- 被 Agora 记录为可审计的任务过程。

任务完成后：

- AI 工具自动整理本次任务上下文。
- AI 工具上传 ContextUpdate 到 Agora。
- 项目经理或技术负责人在 Web UI 中评审并合并。
- AI 工具可以总结候选 skill。
- 候选 skill 由实际人员在 Web UI 审批后入库。

## 上下文一致性和自动化

多个开发人员处理同一个项目时，Agora 应保持团队上下文一致。

理想体验：

- 开发人员不手动判断上下文是否最新。
- AI 工具自动检查 freshness。
- AI 工具自动使用旧上下文并在后台更新。
- 对隐私、冲突、高成本扫描、关键审批场景才打断用户。
- 主干上下文可以由 CI 或具备本地代码访问权的 AI 工具自动更新。

Agora 需要管理：

- ContextPack 版本。
- 任务 ContextUpdate。
- 上下文来源引用。
- 上下文审核状态。
- 上下文合并记录。
- 过期、冲突、缺失状态。

## 技能包和团队经验

Agora 管理的 skill 不是普通工具脚本，而是团队工作方法、流程规范、检查清单、任务经验和 AI 工作策略。

skill 来源包括：

- 项目经理/技术负责人手工维护。
- 管理员通过 AI 工具生成。
- 开发人员在任务中让 AI 工具总结候选 skill。
- 多次 accepted writeback 中提炼出的团队经验。

skill 入库必须可治理：

- 候选。
- 草稿。
- 已批准。
- 已废弃。
- 版本化。
- 审批审计。

## Agora 承担的项目管理能力

Agora 不只是上下文存储，也承担一部分项目管理工作。

包括：

- 识别任务名称。
- 如果任务无法识别，允许 AI 工具询问用户补充。
- 记录任务状态。
- 记录每一步流程产物。
- 给项目经理提供任务状态视图。
- 给质量人员提供质量状态视图。
- 对任务过程、上下文更新、skill 提交进行审计。

## 后续研发方向

后续实现应围绕真实工作流重排，而不是继续把 Web UI 的测试页面作为主产品体验。

优先级应调整为：

1. AI 工具侧项目识别和 Agora 项目解析协议。
2. Context freshness check。
3. AI 工具上传 ContextPack / ContextUpdate。
4. 项目流程定义和任务流程执行。
5. 每步固定文档产物和人工审查节点。
6. ContextUpdate Web 审核合并。
7. 候选 skill 上传、审批、入库。
8. 项目经理任务状态视图。
9. 质量人员质量状态视图。
10. 团队资产、项目资产、审计治理。

## 黑盒验收原则

黑盒验收必须基于真实角色和真实 AI 工具路径：

- 开发者通过 AI 工具开始任务。
- AI 工具自动解析项目和任务。
- AI 工具从 Agora 获取上下文、流程和 skill。
- AI 工具按流程输出分析、设计、评审、开发、自测、上传文档。
- AI 工具将任务上下文更新上传 Agora。
- 项目经理在 Web UI 审核合并。
- 质量人员或项目经理通过 AI 工具获取任务/项目状态。

只通过 Agora Web UI 手动跑一个辅助 Context Query，不再算完整黑盒验收。
